# Implementation Plans

Generated by the `improve` skill (deep audit) on 2026-08-08, against commit
`1f7f4e3`. A follow-up deep audit pass on 2026-08-14 (same commit — zero
drift) reconciled the queue and added plans 013–019. Execute in the order
below unless dependencies say otherwise. Each executor: read the plan fully
before starting, honor its STOP conditions, and update your row when done.

This audit read every source file directly (content.js, background.js,
popup/, options/, i18n.js, manifest.json, the test suite, and the packaging
scripts — roughly 2,800 lines total) rather than fanning out subagents,
since the codebase is small enough to fit in full context. Two of the
findings below (the storage-quota cap and the snooze-resume bug) were
verified empirically — byte-exact quota math for #001, direct code tracing
for #002 — rather than estimated.

Plans 007–012 came from a follow-up `next`/direction pass (2026-08-08, same
commit) surveying feature/roadmap opportunities. Two of them (007, 009) are
implementation-ready; three (008, 010, 011) are **design plans** — the
deeper pass that produced them found real architectural decisions
(a page-scanning strategy that doesn't exist yet, a multi-function API
change, a data-shape addition) that shouldn't be pre-baked into
line-numbered steps against code that other plans will change first. One
(012) is a **process plan** — adding a new detection language requires
native-speaker validation this session isn't positioned to fabricate, so
it documents the process rather than shipping unverified regex patterns.

## Direction findings (feature ideas surveyed)

Six feature ideas were surveyed and presented to the maintainer, who
confirmed all six as net-positive and consistent with the extension's
local-only, no-network-requests positioning. All six became plans:

1. **Manage "Not spam" exclusions in the options page** → plan 007. Real
   gap: `ss_excluded` had no management UI at all, unlike the whitelist.
2. **"Always block this author" list** → plan 008 (design). Mirrors the
   existing whitelist conceptually, but needs a page-scanning strategy
   that doesn't exist today — see that plan's "core design tension."
3. **Full settings backup/restore** → plan 009. Export/Import currently
   covers only phrases, not whitelist/exclusions/language toggles.
4. **Show which pattern/phrase triggered each block** → plan 010 (design).
   Also nets a simplification: deletes a block of duplicated
   pattern-rebuilding logic in `blockPost()`.
5. **Per-pattern (not just per-language) built-in toggle** → plan 011
   (design, blocked on 004).
6. **Additional detection languages** → plan 012 (process plan — see why
   this one isn't a code-change plan in its own file).

A seventh idea — shared/remote pattern sync or a community blocklist —
was considered and explicitly rejected; see "Findings considered and
rejected" below.

### Follow-up pass (2026-08-14): new plans 013–019

The second audit found two fresh direction ideas, both confirmed net-positive
against the extension's local-only positioning, and both became
implementation-ready plans:

1. **"Show all hidden posts" popup button** → plan 018. The machinery
   (`restoreBlocked()`) already exists and is wired to disable/snooze but
   no single user-facing action; one message case + one button exposes it.
2. **"Report missed spam" placeholder button** → plan 019. Copies the
   matched post text to the clipboard (user-initiated only — nothing is
   sent by the extension) and opens the pre-filled `missed_spam_pattern`
   GitHub issue form, closing the README's issue-form feedback loop.

## Findings considered and rejected

- **Wrong-author whitelisting via an oversized post-container heuristic**:
  hypothesized that `findBySiblingHeuristic` could occasionally pick a
  container spanning multiple posts, causing "Never block this author" to
  whitelist the wrong profile. Plausible in principle, but verifying it
  requires live-DOM evidence (actual LinkedIn markup triggering the
  heuristic to over-select) that this audit didn't have access to. Not
  planned; if a user report ever surfaces this concretely, re-audit with
  the specific DOM structure that triggered it.
- **`forEachTextNode`'s second `SHOW_ELEMENT` TreeWalker for shadow-DOM
  discovery** (`content.js`, inside `forEachTextNode`): runs unconditionally
  over the full subtree on every scan just to find `shadowRoot`s, even
  though LinkedIn's feed markup rarely uses shadow DOM in practice. Real but
  minor overhead; investigate-level, not planned. Revisit if a future
  profiling pass shows scan latency as an actual user-visible problem.
- **Locale key coverage** (`t()` calls / `__MSG_*__` tokens vs.
  `_locales/en/messages.json`): verified via `grep`+`comm` diff — every key
  referenced in JS and both HTML files exists in the locale file, and vice
  versa (the handful of keys that appeared "unused" were false positives
  from a regex that didn't match `countMessage()`'s dynamic key arguments).
  No gap found; not planned.
- **`options/options.html` element IDs vs. `options.js` `getElementById`
  calls**: verified every ID options.js looks up exists in the HTML. No
  crash risk found; not planned.
- **Multi-tab counter race** (`content.js:796-799`): two LinkedIn tabs can
  overwrite each other's `blockedCount`/`dailyCounts` since each content
  script keeps independent in-memory state. Already documented in the code
  with an explicit comment; the maintainer has already accepted this as
  low-impact/cosmetic. Not re-planned here — see 003 for a related but
  distinct stat-accuracy fix (toggle-triggered double-counting), which is
  in scope because it's a single-tab, single-session bug rather than a
  cross-tab race.
- **ReDoS in the built-in detection patterns** (`content.js`
  `BASE_PATTERNS`, now `shared/pattern-data.js` after plan 004): reviewed
  every pattern for catastrophic-backtracking shapes (nested quantifiers
  like `(a+)+`). None found — all patterns are effectively linear in input
  length. Not planned.
- **Shared/remote pattern sync or community blocklist** (surfaced during
  the `next`/direction pass that produced plans 007–012): a natural-seeming
  extension of the phrase/pattern system — let users pull in
  community-curated phrase lists, or sync detection improvements across
  installs. Deliberately not planned, and shouldn't be without a product
  decision to change course first: it directly contradicts this
  extension's core positioning (README: "no analytics, telemetry, remote
  blocklists, AI APIs, or network requests of any kind"; badges for
  "Local only" / "No telemetry"). Recorded here so it isn't independently
  reinvented and proposed again without that tension being surfaced.

### Added by the 2026-08-14 follow-up pass

- **Popup undo index race** (`content.js` `undoBlock` + `popup.js`'s
  index-based rows): a new block between render and click could shift
  `lastBlocked` and undo the wrong post. Real but narrow — the undo window
  holds at most 5 entries and the shift requires a block landing in the
  same second as a click. Not planned.
- **Options-page whitelist additions don't un-hide already-blocked posts**:
  adding an author to the whitelist in options leaves their currently
  hidden posts hidden until reload or manual "Show". The in-flow "Never
  block this author" button already restores immediately; impact is
  limited to a rare edit-after-the-fact path. Not planned.
- **UTC-based "today" stats bucket**: `getTodayKey()` and the popup both
  use `toISOString()` UTC days, so the "today" boundary sits at UTC
  midnight rather than the user's local midnight. Internally consistent
  (both sides agree), purely cosmetic. Not planned.
- **`isCustom` pattern-rebuilding duplication in `blockPost()`**
  (`content.js:692-707` recompiles per-post regexes identical to
  `buildPatterns`'s logic): already folded into plan 010's scope ("deletes
  a block of duplicated pattern-rebuilding logic"); a standalone fix would
  double that work. Not separately planned.
- **Starter-pack exact phrases amplify false positives** ("COMMENT",
  "PDF", "10x" as whole-word exact matches will hide legitimate posts
  containing those words): deliberate, opt-in product behavior with a
  built-in undo path. Not planned.
- **`MAX_EXCLUSIONS` FIFO silent eviction** (oldest 100 exclusions drop
  off, silently re-blocking previously-excluded texts): plan 007's
  exclusion-management UI makes this visible and manageable. Not
  separately planned.
- **Dead `showCooldowns` cooldown in `content.js`**: NOT rejected — this
  became plan 013 (removes the dead branch and implements the documented
  15-minute protection keyed by post identity). Recorded here so no future
  audit reports it as new.

New findings surfaced during execution (not previously planned):

- **ES-1 pattern `\b` quirk (latent detection bug, discovered during plan
  011)**: in `shared/pattern-data.js` ES-1, the `env\u00ed|enviar\u00e9|dar\u00e9`
  alternatives are followed by `\b`, which can never match in a non-unicode
  regex (accented chars are non-word, so no boundary exists after them).
  Result: the most common Spanish bait forms ("comenta X y te envío el
  PDF", "...enviaré...", "...daré...") never match ES-1; only
  `comparto|mando|doy|regalo` alternatives fire. Fix sketch: drop the `\b`
  or replace with `(?!\w)` lookahead in ES-1 only. Not planned — it's a
  sensitive detection-pattern change with false-positive risk; the
  maintainer should weigh it. Verification was one-liner: `node -e
  "console.log(/(?:comenta)[^]*?enviar\u00e9\b/i.test('comenta X y te
  enviaré el PDF'))"` → false.
- **Toggle-on duplicate placeholder (fixed by plan 020)**: three separate
  executors (003, 013, 014) independently hit the double-scan race before
  it was characterized and fixed in 020. The 003/013-era loose assertions
  were tightened to exact counts afterward.
- **`release.yml` never runs Playwright** (plan 017 premise correction):
  the release `package` job is smoke+package only; the CI cache plan was
  scoped to `ci.yml` accordingly.
- **`node --test tests/unit/` directory form is broken on Node 24** (plan
  005): the `test:unit` script uses the glob form `node --test
  "tests/unit/*.test.js"` — documented in plan 005's command table.
